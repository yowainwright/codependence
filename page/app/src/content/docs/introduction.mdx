## Check a dependency policy

Put a `.codependencerc` at the root of your project. This policy tells Codependence to keep React on the `^19.0.0` range in the app’s `package.json`.

```json {6} title=".codependencerc"
{
  "config": {
    "app": {
      "path": "package.json",
      "manager": "pnpm",
      "codependencies": [{ "react": "^19.0.0" }]
    }
  }
}
```

Run `codependence` to check the manifest. To preview the edits the policy would make, run:

```sh
codependence --update --dryRun
```

## Synopsis

Each manager target gets its own files and policy. Codependence loads the config once, verifies every target, and can fail CI or update mismatched manifests.

See [Policy Surface](/docs/policy-surface/) for what Codependence supports today and where the same policy model can expand next.

## Why use Codependence?

- Define the versions that must stay current or pinned
- Manage multiple dependency managers from one `.codependencerc`
- Fail local checks or CI when dependency versions drift
- Update only listed packages, or update everything except listed packages
- Apply package-specific policy across monorepos
- Run from npm scripts, GitHub Actions, or custom Node tooling

## Why not use Codependence?

Skip it if hosted dependency PRs from Dependabot or Renovate already cover your workflow and you do not need local or CI policy enforcement.
