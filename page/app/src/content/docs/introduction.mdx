**One configuration for every dependency manager.**

**Codependence** checks and updates dependency versions using [one-to-many](https://en.wikipedia.org/wiki/One-to-many_%28data_model%29) project policies with support for Node, Python, Go, Rust, Docker, GitHub Actions, and Helm.

This means you control how you update and why you update dependencies. Versus other tools, Codependence caters to a project's context vs a dependency's context.

## Main Use Case

**Pin lodash and update the rest**

Suppose your app needs lodash `4.17.21`. Declare that exact version in `package.json`. Put this config beside it to keep lodash there while updating the other packages and Docker base images to their latest eligible versions.

<CodeDemo label="Configure both updates" steps={[
  { line: 7, label: "Hold back lodash", note: "In precise mode this list names the exceptions. Lodash keeps its declared version." },
  { line: 12, label: "Update base images", note: "There are no exceptions for this Dockerfile. Codependence looks up the latest compatible image tags." },
]}>

```json title=".codependencerc"
{
  "config": {
    "app": {
      "path": "package.json",
      "manager": "pnpm",
      "mode": "precise",
      "codependencies": ["lodash"]
    },
    "image": {
      "path": "Dockerfile",
      "manager": "docker",
      "mode": "precise"
    }
  }
}
```

</CodeDemo>

## Preview the change

From the project root, preview both updates.

```sh
pnpm dlx codependence --update --dryRun
```

For example, if React resolves to `19.1.0` and Alpine to `3.20`, the diff includes both updates. Lodash stays at `4.17.21`.

<CodeDemo label="Review the two changes" steps={[
  { line: 4, label: "Pinned package", note: "Lodash appears as context in the diff. Its version stays at 4.17.21." },
  { line: 6, label: "React update", note: "React is outside the exception list, so its version updates." },
  { line: 11, label: "Alpine tag", note: "The same run updates the Docker base image." },
]}>

```diff title="Proposed changes"
--- a/package.json
+++ b/package.json
@@ -4,2 +4,2 @@
     "lodash": "4.17.21",
-    "react": "19.0.0"
+    "react": "19.1.0"
--- a/Dockerfile
+++ b/Dockerfile
@@ -1 +1 @@
-FROM alpine:3.19
+FROM alpine:3.20
```

## Open one pull request

Save this workflow and [configure the repository token](/docs/github-action/#token-screen). It runs on Mondays at 09:00 UTC. You can also start it manually from GitHub Actions.

<CodeDemo label="Schedule one update pull request" steps={[
  { line: 16, label: "Both targets", note: "This job runs pnpm and Docker together using the same .codependencerc." },
  { line: 20, label: "One pull request", note: "When either target changes, the action opens or refreshes one PR for the pair." },
]}>

```yaml title=".github/workflows/update-dependencies.yml"
name: Update dependencies
on:
  schedule:
    - cron: "0 9 * * 1"
  workflow_dispatch:

jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 # v7.0.0
        with:
          persist-credentials: false
      - uses: yowainwright/codependence@add92453b85ffafb511988545fc153ba25b04792 # v1.1.1
        with:
          targets: |
            pnpm
            docker
          version: pnpm=11.21.0
          pull-request: true
          token: ${{ secrets.CODEPENDENCE_TOKEN }}
          post-update-command: pnpm install
```

</CodeDemo>

## Apply it locally

```sh
pnpm dlx codependence --update
pnpm install
```

The first command edits `package.json` and `Dockerfile`. The second installs the packages and refreshes `pnpm-lock.yaml`.
